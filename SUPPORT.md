# Support

## Before asking for help

1. Read the relevant guide in [`docs/`](docs/).
2. Search existing issues and discussions.
3. Confirm the problem on a clean checkout when possible.
4. Remove credentials, personal information, and production identifiers from logs and examples.

## Where to ask

- **Bug or reproducible behavior:** open a GitHub issue using the bug report template.
- **Feature proposal:** open an issue using the feature request template.
- **Documentation problem:** use the documentation update template.
- **Usage question:** use GitHub Discussions when enabled, or open a clearly labeled support issue.
- **Security vulnerability:** follow [`SECURITY.md`](SECURITY.md), not the public tracker.

## What to include

Please provide:

- Operating system and versions of Node.js, npm, Python, Docker, and the relevant model/runtime.
- Service directory and commit or branch.
- Exact command used.
- Expected and actual behavior.
- A minimal, sanitized log or request example.
- Whether the issue occurs in Docker, local development, or a deployed environment.

Community support is volunteer-based and there is no guaranteed response time. Production incidents should be handled through the deployment owner's operational process.
